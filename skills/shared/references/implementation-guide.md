# Implementation judgment

Use the approved goal, acceptance conditions and boundaries as the contract. Continue reasoning while implementing. Read the current code, test assumptions and adapt private implementation details when evidence warrants it.

A local import, private name, algorithm or test arrangement can change within the sealed behavior, scope and verification basis. Record the reason in a separate work note and run relevant checks. Do not edit an approved plan just to log progress: that changes its source digest. The runtime records progress from evidence.

A changed public interface, authorized file set, oracle, invariant, persistent state contract or execution basis needs a journalled replan. Preserve the observation and invoke the applicable authenticated discovery/risk/root-cause route. Existing authorization for internal implementation and replan continues to apply. Ask the user only when their intent is ambiguous or a required action exceeds actual authorization; a plugin preference never grants external permission.

Choose verification proportionate to the change. Strict slices retain genuine RED/proof/GREEN. Outcome slices use positive and counterexample observations without inventing a failing test. A legitimate already-correct result needs the runtime's unchanged-source observation, followed by the same verification and goal acceptance checks.

Use the public runtime for activation, scoped writes, result capture, review, completion and recovery. Never author completed receipts, approval hashes or phase flags yourself. Read `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/runtime-execution-spine.md` for the current command flow.

If a dependency is needed, first inspect the project manifest and lockfile. Use the runtime's narrow environment preparation route when its exact operation is already authorized. If the recipe is unsupported, explain the concrete missing capability and continue independent work; do not substitute an arbitrary install or an artificial passing check.

The current model remains the implementer by default. Explicit delegation or a specific available model takes precedence. Native tools determine available delegation, not whether a tool is literally named Agent. Parallel workers prepare patches for serialized application, or use independent sessions/worktrees. A single session has one active slice and one write window.

On failure, diagnose before retrying. Fix legitimate test defects inside the approved contract and verify them; changing acceptance criteria requires replan. Retain healthy sibling receipts. Use the runtime's scoped recovery operation; never reset or stash unrelated user changes.

Report observable progress and evidence gaps concisely. Continue authorized work until the requested outcome and terminal receipt are complete. A missing public receipt should trigger republication, not repeated implementation or external effects.
