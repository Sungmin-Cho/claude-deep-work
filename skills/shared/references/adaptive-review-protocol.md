# Independent review execution

Compile roles, tier floors, evidence requirements and available transport using `${CLAUDE_PLUGIN_ROOT}/runtime/review-policy-runtime.js`. The policy decides requirements; a scheduling preference cannot remove High/Critical required roles. Native capability is observed from actual tools, never inferred from a host name or a literal Agent tool check.

Prefer the runtime-generated artifact/global review packet and its thin review-run route, which derive request/prompt/binding from current evidence. Use `review execution run` from the contained `${CLAUDE_PLUGIN_ROOT}/scripts/deep-work-runtime.js` for governed evidence. Bind exact request/prompt/artifact/contract/policy/source/dependency/recovery identities. The producer records raw output, exit/timeout/overflow and requested/effective/observed model/effort/session data. Caller-supplied status or PASS is not a producer receipt.

A result qualifies only with authenticated successful execution and the required actual identity/role/tier. Codex host trace metadata can establish observed model only when bound by the runtime to the fresh thread, cwd and launch interval; argv or model prose cannot. Missing observed model stays unknown. Without an explicit model pin, retry an unavailable/nonqualifying transport on a new available CLI seat with the same requirement/binding. Preserve failed attempts; disclose same-family diversity. Explicit unavailable pins require a user model choice, not silent substitution.

First-round reviewers receive the target and necessary contract/source context, excluding the author's conclusion and other reviewers' findings. Sequential execution can preserve this independence. A reviewer returns evidence-grounded findings; the author validates and applies or rejects them. Findings must identify a violated contract, concrete scenario and source evidence.

Recheck material open findings against the corresponding correction. Do not repeat solved issues or re-run the entire review without new cause. Use the compiled round budget; unresolved evidence is adjudicated by the main agent when within authorization, with human input only for genuinely missing intent/authority.

Reuse requires exact current request/artifact/contract/policy/dependency/source/generation plus qualifying role/model/tier/channel/session identities and terminal success. Reuse is not copying a previous PASS string. Per-ID outcome review additionally binds positive/control refs and counterexample relevance; every required ID must be satisfied with appropriate evidence.

Persist findings and approvals through runtime publication. Do not edit reviewed flags, review_execution_json or receipt authority manually. Read `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/runtime-execution-spine.md` for producer and continuation flow.

For sandbox app-server/authentication failures, use the already authorized concrete runtime review command with the host's per-command approval mechanism; never globally disable sandboxing or modify credentials/caches. Preserve the failed attempt and inspect actual child status after retry. Follow the transport recovery section in `${CLAUDE_PLUGIN_ROOT}/skills/shared/references/runtime-execution-spine.md`.
